## 이웃 메모

이웃마다 호칭(예: "봄비님"), 말투(존댓말/반말), 친밀도(1~3), 자유 메모를 둔다. 호칭과 말투는 초안 프롬프트에 그대로 들어간다.

이웃 목록에는 "마지막으로 댓글 남긴 날"을 보여주고, 오래 안 간 순서로 정렬할 수 있다. 새 글이 있는데 30일 넘게 못 간 이웃은 강조한다.

## 글 상태

`새 글 → 읽음(웹뷰에서 엶) → 댓글 남김 | 건너뜀`. 이와 별도로 사용자가 직접 누른 공감을 감지해서 "공감함" 표시를 붙인다.

## 마실 모드

- "마실 시작"을 누르면 처리하지 않은 새 글을 오래된 순서대로 하나씩 연다.
- 댓글을 등록하거나 건너뛰면 다음 글로 넘어간다. 다 돌면 "오늘 마실 끝" 화면을 보여준다.
- 단축키: `→` 다음, `S` 건너뛰기, `1`/`2`/`3` 해당 초안 채우기.

- 들른 글은 그 바퀴 동안 다시 열지 않는다. 댓글 없이 넘긴 글은 "읽음"으로 남아 다음 바퀴에 다시 나온다.
- 등록이 확인되면 1.5초 뒤 다음 글로 넘어간다. 단축키는 앱 화면에 포커스가 있을 때만 동작한다(웹뷰에서 입력 중인 키를 가로채지 않기 위해).

## 이웃 가져오기

- 순서: 네이버 로그인 → 내 블로그 찾기 → 웹뷰에 이웃 관리 화면(`admin.blog.naver.com/BuddyListManage.naver?blogId=`) 열기 → "읽기".
- "읽기"는 웹뷰의 모든 프레임에서 블로그 홈 링크(`blog.naver.com/{id}`)를 모은다. 이웃 목록 영역 선택자는 `src/preload/naver-selectors.ts`의 `buddyList` 후보이고, 못 찾으면 화면 전체 링크를 읽은 뒤 사용자가 고른다.
- 목록이 여러 쪽이면 사용자가 웹뷰에서 쪽을 넘기고 다시 읽는다. 읽은 후보는 모인다.
- 고른 이웃은 공통 요청 큐로 하나씩 RSS를 확인해 등록한다(3~6초 간격). 처음 등록할 때처럼 기존 글은 "이미 본 글"이 된다.
- 2026-11-17 기준, 로그인 상태의 이웃 관리 화면 구조는 아직 확인하지 못했다. 실제로 써 보고 `buddyList` 선택자를 맞춘다.

## 확인 주기와 알림

- 앱을 켤 때 한 번 전체를 확인하고, 그 뒤로는 주기적으로 확인한다. 주기는 기본 30분, 최소 10분.
- 이웃 요청은 순차로 보내고 사이에 3~6초 랜덤 지연을 둔다.
- ETag나 Last-Modified를 주는 경우 조건부 요청(304)을 쓴다. 연속으로 실패하는 이웃은 확인 간격을 점점 늘린다.
  - 2026-11-17 확인: 네이버 RSS는 ETag와 Last-Modified를 주지 않는다. 그래서 실제로 부담을 줄이는 건 확인 주기와 요청 간격이다.
  - 없는 블로그도 200 응답에 빈 채널(제목 없음, 글 없음)을 준다. 이 경우를 "블로그를 찾지 못함"으로 처리한다.
  - 앱이 보내는 모든 자동 요청은 `src/main/naver-request.ts`의 큐 하나를 거친다(순차 실행 + 3~6초 간격).
- 알림은 확인 한 번당 하나로 묶는다(예: "새 글 3개: 봄비님, 하늘다람쥐님 외 1명"). 알림을 누르면 첫 번째 새 글로 간다.
- 방해 금지 시간대(예: 23시~8시)를 설정할 수 있다.

## AI 초안

- OpenAI 호환 API를 쓴다. 설정에서 Base URL, API 키, 모델명을 입력한다(OpenAI, OpenRouter, Ollama 등).
- 톤 3종이 기본값이고, 이름과 설명은 설정에서 고칠 수 있다.
  - 다정한 공감
  - 짧고 가볍게
  - 질문으로 잇기
- 글이 다 뜨면 자동으로 생성한다. 설정에서 수동 생성으로 바꿀 수 있다. "다시 쓰기" 버튼은 항상 있다.
- 시스템 프롬프트는 고정이고, temperature는 0.4, 출력은 JSON `{"drafts":[{"tone","text"}]}`으로 받는다.
- 프롬프트에 넣는 내용(개수는 설정에서 조정 가능):
  - 본문 앞쪽 약 3,000자
  - 사진 설명, 장소, 태그
  - 최근 내 최종 댓글 5개
  - 이 이웃에게 쓴 과거 댓글 3개
  - "초안 → 최종본" 쌍 3개
  - 스타일 가이드 전문
  - 이웃 메모
- 금지 규칙: "좋은 글 잘 보고 가요" 같은 상투적인 표현을 쓰지 않는다. 본문의 구체적인 내용을 최소 1개 언급한다.
- 이미지도 AI에 보낼 수 있다. 설정의 "본문 이미지도 AI에게 보내기" 옵션으로만 켜고, 기본은 꺼짐이다. 비전 모델이라도 옵션이 꺼져 있으면 보내지 않는다(모델 이름으로 자동 판단하지 않는다). 켜면 글마다 최대 4장(한 장 1.5MB 이하)을 보낸다. 설정 화면에 이미지가 토큰을 많이 써서 비용이 늘 수 있다는 안내를 둔다.

## 네이버 글 화면 구조 (2026-11-17 확인)

- 글은 `mainFrame` iframe의 `PostView.naver` 문서 안에 있다.
  - 제목: `.se-title-text`
  - 본문: `.se-main-container`
  - 태그: `.wrap_tag a`
- 공감 버튼은 `.u_likeit_button`이다.
- 댓글 영역은 처음에 접혀 있다.
  - "댓글 N" 토글(`#Comi{logNo}`)을 눌러야 cbox가 로드된다.
  - 로드되면 입력칸은 `div.u_cbox_text[contenteditable]`, 댓글 항목은 `.u_cbox_comment`, 댓글 내용은 `.u_cbox_contents`이다.
- **결정**: "채우기"를 누르면 접힌 댓글 영역을 앱이 펼친다. 앱이 누를 수 있는 버튼은 이 토글 하나뿐이고, 등록·공감 버튼은 누르지 않는다. CLAUDE.md 원칙 1에도 적었다.

## 최종본과 스타일 학습

- 초안은 패널에서 고친 뒤 "채우기"로 댓글 입력칸에 넣는다.
- 등록 클릭을 감지하면 그 순간의 입력칸 내용을 "최종본 후보"로 저장한다. 그 뒤 댓글 목록에 같은 내용이 나타나면 "등록 확인됨"으로 확정한다. 비밀 댓글 여부도 기록한다.
- 학습용 쌍은 "마지막으로 채운 초안"과 "최종본"이다. 직접 쓴 댓글은 최종본 예시로만 쓰고 수정 패턴 학습에는 넣지 않는다.
- 스타일 가이드: 최종본이 새로 10개 쌓일 때마다 AI가 개정안을 만든다. 설정 화면에 기존 가이드와의 차이를 보여주고, 사용자가 승인해야 반영된다. "지금 정리하기" 버튼이 있고, 가이드를 직접 고칠 수도 있다.
  - 거절한 개정안도 기준점이 된다. 거절 직후 같은 개정안이 다시 오지 않고, 다시 10개가 쌓여야 새 개정안을 만든다.
  - 직접 고친 가이드는 바로 적용된다. 비워서 적용하면 초안에 가이드를 넣지 않는다.

## 화면

- 디자인 방향은 시안 C "출석부 공책"이다. 시안 파일은 `design/mockups/`에 있다.
- 3단 레이아웃:
  - 왼쪽: 출석부(새 글과 이웃 목록)
  - 가운데: 블로그 웹뷰
  - 오른쪽: 위에서부터 초안 → 이웃 수첩 → 지난 댓글. 색인 탭으로 각 영역에 이동한다.
- 패널 경계선을 끌어서 폭을 바꿀 수 있고 그 폭을 기억한다. 오른쪽 패널은 접을 수 있다. 창 최소 크기는 1200×760.
- 초안 본문은 줄 없는 종이 바탕에 둔다. 공책 줄은 그 밖에만 보인다(가독성).
- v1은 라이트 테마만 만든다.
- 폰트는 함렡, IBM Plex Sans KR, 감자꽃이고 모두 OFL 라이선스다. fontsource로 앱에 포함한다.
- 창의 X 버튼은 트레이로 숨긴다. 완전히 끄려면 트레이 메뉴의 "종료"를 쓴다. 윈도우 시작 시 자동 실행 옵션이 있고, 이때는 숨긴 상태로 시작한다.

## 기술

- electron-vite 6, Electron 45, Svelte 5, TypeScript 5.9를 쓴다. TS 7은 svelte-check가 지원하지 않아서 쓰지 않는다.
- DB는 better-sqlite3다. 네이티브 모듈이라 Windows 빌드는 Windows 러너에서 한다.
- RSS는 fast-xml-parser로 파싱한다. AI 호출은 `openai` SDK에 baseURL을 바꿔 끼워서 한다.
- 네이버 화면은 WebContentsView로 띄우고, 세션은 `persist:naver`, UA는 일반 크롬 UA를 쓴다.
- preload는 sandbox에서 돌기 때문에 진입점마다 단일 CJS 파일로 빌드한다(`isolatedEntries`).
- API 키는 safeStorage로 암호화한다. AI 호출은 메인 프로세스에서만 한다.
- 텔레메트리는 없다. 로그는 로컬에만 남기고 일정 크기가 넘으면 순환한다. 키와 본문은 기록하지 않는다.
- 데이터 내보내기·가져오기는 SQLite 파일을 통째로 복사하는 방식이다(`db.backup`). 가져오기 전에 현재 데이터를 `userData/backups/`에 자동으로 백업하고(최근 5개 유지), 가져온 뒤 앱을 다시 시작한다.
  - 내보낸 파일에는 암호화된 API 키도 넣지 않는다(삭제 후 VACUUM). 가져올 때는 지금 쓰던 키를 그대로 옮긴다.

## 배포

- 저장소는 Public이고 라이선스는 MIT다.
- Windows .exe(NSIS)만 배포한다. 코드 서명은 하지 않으므로 처음 설치할 때 SmartScreen 경고가 뜬다.
- `v*` 태그를 push하면 GitHub Actions의 Windows 러너가 빌드해서 GitHub Releases에 올린다. 버전은 0.1.0부터 시작한다.
- electron-updater: 앱을 켤 때와 6시간마다 확인하고, 백그라운드에서 받은 뒤 다시 시작할지 묻는다. 강제하지 않으며, 미루면 종료할 때 설치된다.
